# 任意座標系 地図XML 位置合わせ 設計

ステータス: ドラフト（2026-10-26 更新: 基盤地図情報を加えた2段構えで熊野町の団地を位置合わせできた）

## 1. 目的とスコープ

法務省 登記所備付地図データ（地図XML）のうち `<座標系>任意座標系</座標系>` の地区について、
公共座標系（JGD2011 平面直角座標系。広島県は第III系 EPSG:6671）への変換パラメータを推定し、
位置合わせ済みの筆ポリゴンと品質指標を出力する。

- 全自動で全地区を正しく合わせることは目標にしない。
  **「自動で確定」「自動＋人の確認」「位置合わせ不可」に振り分け、人の作業を確認と例外処理に絞る**のがゴール。
- 最初の対象は広島県（0.5m DEM がオープンデータで、公共座標系の地区も多い）。
- QGIS / GDAL/OGR の機能はすべて使える前提。独自実装は「スコア計算と探索」に限定し、
  前処理・変換・確認は既存ツールに寄せる。

## 2. 前提として確認したこと / 未確認のこと

| 項目 | 状況 |
|---|---|
| XML の構造 | `地図` 直下に `座標系`、`空間属性`（GM_Point/Curve/Surface）、`主題属性`（筆・筆界点・筆界線）、`図郭` |
| 座標の軸 | `zmn:X` が北方向、`zmn:Y` が東方向（測量座標）。GIS に載せるときは入れ替える |
| 任意座標系の値 | 原点付近の数百 m 程度の値（例: 広島市中区で X,Y ≈ -750〜+90） |
| 図郭の属性 | `方位不明フラグ`、`縮尺分母`、`地図種類`、`地図分類`、`地図作成年月日` がある |
| 14条地図でも任意座標系がある | 確認済み（中区の土地区画整理所在図 1970年、法第14条1項地図、任意座標系） |
| 1つの XML 内の図郭どうしが同じ局所座標系を共有するか | **地区による**。広島市中区は 68 地区中 47 が隣接（共有）、8 が重なる（図郭ごとに別）。熊野町は 11 地区すべてで図郭が離れている。→ 距離でクラスタリングした「エリア」を単位にする |
| 公共座標系の「地区外」擬似筆 | 地番が `地区外-…` の筆が、地籍調査区域外を図郭単位の長方形で埋めている（熊野町 589 筆・7.85 km²）。線は実在しないので参照エッジ・禁止領域から除く |
| 地番のジオコーディング | 住居表示未実施の地域では、国土地理院の住所検索で「大字＋本番」が番地単位で引ける（熊野町で確認） |
| `方位不明フラグ=true` の頻度 | **未確認**（県全体の集計で調べる） |
| 道路・水路の筆の表現 | **未確認**（地番が空なのか「道」「水」なのか、筆として存在しないのか） |

## 3. 全体の流れ

先行研究（梅原ほか 2024）の「地番のジオコーディングによる相似変換」で粗く合わせ、
DEM・公共座標系の筆界とのチャンファーマッチングで細かく合わせる2段構えにする。

```
地図XML ──▶ 筆ポリゴン（局所座標）
              │
              ▼
 ① エリア分割（距離 15m 以内の筆をまとめる。図郭ごとに座標系が違う場合に対応）
              │
              ▼
 ② 粗い合わせ: 本番ごとの重心 ↔ 地番のジオコード結果（国土地理院 住所検索）
              相似変換を最小二乗で推定し、外れ値（Q3+1.5IQR）を除いて再推定
              ※対応点が 3 未満のエリアは、大字の範囲から全域探索（③）に回す
              │
              ▼
 ③ 細かい合わせ: 向き付きチャンファーマッチング
              参照 = DEM 曲率エッジ（0.5m）＋ 公共座標系の筆界（地区外は除く）
                     ＋ 国土地理院 基盤地図情報の道路縁・水涯線（ベクトルタイル experimental_fgd）
              罰則 = 公共座標系の筆・配置済みエリアとの重なり ＋ 筆の内部の地形エッジ密度
                     ＋ 建物（基盤地図情報の建築物外周線）の内部を通る筆界
              1周目: ②の結果の周り（±80m・±8°）を探索
              2周目: 信頼できなかったエリアを、信頼できたエリアの回転の中央値を中心に ±250m で探し直す
              信頼度 = 1位と2位の評価値の差（gap）
              │
              ▼
 ④ 品質評価と振り分け A/B/C → ⑤ 出力（GPKG・QGIS 確認用プロジェクト）
```

### 先行事例

| 事例 | 手法 | 結果 |
|---|---|---|
| 梅原ほか（2024）土木学会 AI・データサイエンス論文集 5(1) | エリア分割 → 地番を Yahoo! ジオコーダで引く → 重心との相似変換 → 外れ値除去 | 徳島市 100 エリア中 60 成功（目視）。明治公図で形が不正確な場合、ジオコードが少ない・偏る場合に失敗 |
| NTT データ BizXaaS MaP | 区画の結合と歪み補正を AI で自動化（非公開） | 全国の任意座標系 約 1.7 億筆を可視化（有償） |
| Siriba & Dalyot（FIG 2011） | 順位付きハウスドルフ距離による自動登録 | ICP は局所歪みと初期対応の欠如で破綻しやすい |

### これまでの検証結果（熊野町）

**評価（公共座標系の図郭を崩して戻す、同じ 20 図郭・探索範囲 ±300m）**

| 参照データ | 成功（誤差 5m 未満） | 誤差 2m 未満 | 成功時の平均誤差 |
|---|---|---|---|
| DEM のみ | 5/20 | 2 | 2.16 m |
| DEM＋公共座標系の筆界 | 6/20 | 4 | 1.85 m |
| DEM＋基盤地図情報 | 14/20 | 12 | 0.83 m（中央値 0.59 m） |
| DEM＋公共座標系の筆界＋基盤地図情報 | 14/20 | 14 | 0.68 m（中央値 0.58 m） |

- gap ≥ 0.5 のものは 1 件も誤りがない（10〜12 件すべて成功）。失敗 6 件はすべて gap ≤ 0.17。
  → gap を A/B/C 振り分けの指標に使える。
- 失敗は筆数の少ない図郭（24〜62 筆）に多い。

**任意座標系への適用（熊野町の団地、柿迫・貴船・神田・石神・東山 15A01、19 エリア）**

- 地番ジオコード→DEM＋基盤地図情報（2周）で、17 エリアが gap ≥ 1。回転は +0〜+10°（中央値 +6.7°）に揃った。
- オルソ画像（広島県 DoboX、20cm、2016 年度）との目視で、区画 1 つに家 1 軒が収まり、街区の外周が道路縁に沿う。
  誤差は目視で 1m 前後。gap < 1 の 2 エリアは団地の外にずれており、判定どおり。
- 熊野町15A05（1,038 筆）など地番に数字がない地区、貴船などジオコードが引けない地区は未対応。

**以前の結果（参考）**

- DEM・筆界だけの全域探索（③のみ）: 公共座標系の図郭を崩して戻す評価で 12 件中 5 件成功（誤差 1.8〜4.1 m）。
  距離のみのチャンファーでは 1/12。森林の DEM エッジの雑音に引き寄せられるのが主な失敗原因で、
  向き付きにして改善した。筆数の少ない図郭で失敗しやすい。
- 任意座標系の地区への適用（③のみ、地区単位）: 回転・縮尺が探索範囲の上下限に張り付き、失敗。
  地区内の図郭が別座標系であること（エリア分割をしていなかった）が一因。

## 4. 各段階の設計

### ① 単位分割

- mojxml で地区 XML を筆ポリゴンに変換する（任意座標系も含める設定）。
- 筆どうしの隣接（境界共有）でグラフを作り、連結成分を「ブロック」とする。
  ブロックごとに独立した局所座標系かもしれない前提で、位置合わせはブロック単位に行う。
- ブロックの特徴量を記録する: 面積、筆数、外周形状、大字名、図郭の地図種類・作成年・縮尺・方位不明フラグ。

### ② 粗い配置（探索範囲を決める）

優先順に使う。

1. **同じ市区町村の公共座標系地区のうち、同じ大字・丁目を持つもの**。
   その地区の範囲＋周辺数百 m を探索範囲にする。一番信頼できる。
2. 大字・町丁目の代表点や境界（国土数値情報、e-Stat 小地域、位置参照情報 大字・町丁目レベル）。
3. 上記がなければ市区町村の範囲全体（探索のコストが大きいので最後の手段）。

あわせて、**公共座標系の筆がすでにある場所は探索から外す**（重なる位置にあるはずがない）。

### 参照データ（合わせる相手）とコスト画像

位置合わせは「ブロックの筆界線が、参照データの線にどれだけ近いか」で評価する（チャンファーマッチング）。
参照データの線をラスタ化して距離変換すると、筆界線上の点でその画素値を引くだけでスコアが出る。

| 参照レイヤ | 作り方（既存ツール） | 効く場所 |
|---|---|---|
| 公共座標系の隣接地区の外周線 | mojxml → `ogr2ogr` / QGIS「ディゾルブ」→ 境界線 | 地区の端の合わせ込み。最も強い |
| 基盤地図情報 道路縁・水涯線・軌道 | 基盤地図情報（2500レベル）→ GPKG | 市街地・平地の骨格 |
| 基盤地図情報 建築物外周線 | 同上（重みは低め。建物と筆界は一致しない） | 市街地 |
| DEM エッジ（傾斜の変わり目・尾根谷・段差） | 0.5m DEM → `gdaldem slope`、QGIS/SAGA で曲率・CS立体図 → しきい値でエッジ化 | 山林・農地・棚田 |
| オルソ画像のエッジ（任意） | 将来の検討。道路・畦の自動抽出が必要 | 補助 |

- 各レイヤを `gdal_rasterize` で同じグリッド（0.5〜1m）にラスタ化し、
  `gdal_proximity` で「最寄りの線までの距離」画像にする。
- 距離の上限（例: 10m）で打ち切り、レイヤごとの重みを付けて合成する。
- 筆界側も重みを付ける: 道路・水路に面した辺、大字境界、ブロックの外周は重みを大きくする。

### ③ 全域探索

- 変換モデル: 相似変換（平行移動 tx, ty・回転 θ・縮尺 s）。
  - `方位不明フラグ=false` なら θ は ±数度に絞る。`true` なら 360° を探索する。
  - s は 0.97〜1.03 程度（公図の伸縮）から始める。
- 粗い解像度（例: 8m グリッドの距離画像）→ 細かい解像度へピラミッドで絞り込む。
- 評価関数: 筆界線上のサンプル点（1m 間隔）で距離画像を引き、ロバスト平均（上限で打ち切った平均）を取る。
  numpy でのサンプリングだけで速く回せる。
- 上位 N 候補を残して次の段階へ渡す（局所解に陥るのを避けるため）。

### ④ 精密化

1. **相似変換の最適化**: 上位候補から、ICP（筆界点 ↔ 参照線の最寄り点）または
   Nelder-Mead でコストを最小化する。
2. **局所補正（公図の歪み対策）**: ブロックをさらに小さな領域（数十筆程度、または格子）に分け、
   各領域で小さな平行移動・回転を推定する。隣どうしの差が大きくならないよう正則化をかける。
   領域ごとの結果から **GCP（変換前 → 変換後の対応点）** を作る。
3. 最終変換は **`ogr2ogr -gcp ... -tps`**（薄板スプライン）や `-order 1/2`（多項式）で実行する。
   GCP は QGIS ジオリファレンサーの `.points` 形式でも出力し、人が開いて直せるようにする。

### ⑤ 品質評価と振り分け

| 指標 | 意味 |
|---|---|
| 残差（筆界線と参照線の平均距離・中央値） | どれだけ線に乗っているか |
| 一致率（距離 2m 以内に乗った筆界線の割合） | 部分的にしか合っていないかの判定 |
| 縮尺のずれ \|s − 1\|、局所補正の大きさ | 歪みの大きさ（大きければ団子図の疑い） |
| 隣接する公共座標系地区との重なり面積・隙間 | 位置の矛盾 |
| 1位と2位の候補のスコア差 | 解の一意性（差が小さければ自信がない） |

- **A: 自動で確定** — 相似変換のみで残差・一致率がしきい値内、候補が一意。
- **B: 自動＋人の確認** — 局所補正で合う、または候補の差が小さい。確認用の QGIS プロジェクトを出す。
- **C: 位置合わせ不可** — 形が合わない。粗い配置（②）だけ出力し、フラグを立てる。

しきい値は⑦の評価データで決める。

### ⑥ 出力

- `out/<市区町村>/<地区>.gpkg`
  - `parcels`: 変換後の筆ポリゴン（EPSG:6671）＋元の属性
  - `blocks`: ブロック単位の変換パラメータ・指標・判定（A/B/C）
- `out/<市区町村>/<地区>.points`: QGIS ジオリファレンサー形式の GCP
- `out/<市区町村>/review.qgz`: 確認用プロジェクト（筆・参照線・CS立体図・地理院地図を重ねたもの）

## 5. 評価方法

正解がないと、しきい値もアルゴリズムの良し悪しも決められない。

1. **合成データ**: 公共座標系の地区を局所座標系に「わざと崩す」。
   ランダムな相似変換＋ノイズ＋なめらかな歪みを加え、元に戻せるかを測る（正解がわかっている）。
   歪みの強さを段階的に変えて、A/B/C の境界を決める。
2. **実データでの目視**: 広島県の任意座標系地区から地図種類・地域（市街地・農地・山林）ごとに
   数地区ずつ選び、結果を QGIS で目視確認する。
3. 指標: 筆の重心位置の誤差（m）、変換後の筆と正解の筆の IoU。

## 6. 「AI」の使いどころ

中心は古典的な位置合わせ（距離変換＋探索＋最適化）で、学習は必須ではない。学習・LLM は次で効く可能性がある。

- DEM / オルソからの線抽出（道路・畦・段差）を、しきい値処理から学習モデルに置き換える。
- B 判定の確認作業の補助（候補の比較、異常の説明）。
- 地区単位でのパラメータ選択（どの参照レイヤを重視するか）。

まずは学習なしで⑦の評価まで通し、足りない部分にだけ導入する。

## 7. マイルストーン

1. **対象の選定**: 県全体の集計はせず、PoC に使う市区町村だけ集計する。
   広島市中区・東区・南区で任意座標系が 528 地区（公共座標系 97 地区）あり、
   市街地の PoC にはこれで足りる。山林・農地向けには DEM の検証時に 1 市町を追加で選ぶ。
2. **単一地区 PoC**: 公共座標系の隣接地区がある任意座標系の地区を1つ選び、
   隣接地区の外周線と基盤地図情報だけで③④（相似変換まで）を通す。
3. **DEM の追加**: 山林・農地の地区で DEM エッジを加え、効果を比較する。
4. **局所補正と GCP 出力**: TPS と QGIS での確認フローまで通す。
5. **合成データによる評価**: しきい値を決め、県全体に流す。
